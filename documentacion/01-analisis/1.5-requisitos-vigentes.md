## 4. Autenticación (cookie + Bearer)

Esto ya está alineado entre el ERS (RF-02, RNF-01) y el código. No hay un segundo mecanismo inventado.

| Cliente | Cómo viaja el JWT |
|---|---|
| Web (React) | Cookie `httpOnly` llamada `sid`. El JavaScript no la lee |
| Flutter | Cuerpo `{ token, usuario }` al entrar/registrarse; luego cabecera `Authorization: Bearer …` |
| Los dos a la vez | Gana la cookie (`extraerToken` en `api/src/auth/token.ts`) |

`GET /auth/yo` **sin** sesión responde **200** con `null` (visitante), no 401. Login fallido: mensaje genérico, no dice si el correo existe.

## 7. RF del ERS vs código (verificación T6)

Se leyó el [1.2](1.2-ers-ieee-830.md) contra `api/README.md` y `token.ts`. RF-02 y RNF-01 **ya** dicen cookie `sid` + Bearer; no se reescribió el ERS entero.

Ajustes puntuales hechos en esta entrega (sin cambiar Must/Should):

- El ámbito del 1.2 nombra el companion Flutter (antes sonaba solo a “sistema web”).
- RNF-01 y la interfaz de comunicación aclaran que **hoy** el prototipo es HTTP local; HTTPS queda si algún día hay piloto en internet.

Nada del ERS afirma recaudo, IoT ni una URL pública.
