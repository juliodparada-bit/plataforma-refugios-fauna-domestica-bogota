Instrumento de planificación. Como Product Owner escribo cada historia Must con identificador, rol, característica, razón y criterios de aceptación, trazada a uno o más RF del 1.2.

**Definición de Terminado (DoD) de una historia:** implementada, cumple los escenarios de aceptación, y no rompe RF-07 (especies) ni la prohibición de recaudo de dinero.

## 3. Historias de usuario — Must

### HU-01 Registro de cuenta

| Campo | Contenido |
|---|---|
| ID | HU-01 |
| Épica | E-01 |
| RF | RF-01 |
| Rol | Como visitante |
| Característica | quiero crear una cuenta con correo, contraseña, localidad y rol |
| Razón | para usar la plataforma según sea adoptante, donante o entidad |
| Prioridad | Must |
| Estimación (relativa) | M |

**Criterios de aceptación**

| # | Escenario | Dado / Cuando / Entonces |
|---|---|---|
| 1 | Registro válido | Dado un correo libre, cuando envío datos completos y acepto el aviso de datos personales, entonces la cuenta queda activa. |
| 2 | Correo duplicado | Dado un correo ya registrado, cuando intento de nuevo, entonces el sistema rechaza y no revela la contraseña ajena. |
| 3 | Entidad sin publicar | Dado que elegí rol entidad, cuando ingreso, entonces no puedo publicar animales ni ítems hasta estar verificado. |

### HU-04 Resolución de verificación

| Campo | Contenido |
|---|---|
| ID | HU-04 |
| Épica | E-01 |
| RF | RF-04, RF-20, RF-21 |
| Rol | Como validador |
| Característica | quiero aprobar, rechazar o pedir complemento |
| Razón | para reducir fraude sin visitar a cada quien |
| Prioridad | Must |

| # | Escenario | Criterio |
|---|---|---|
| 1 | Aprobación | El perfil muestra badge Nivel 1 o Nivel 2 y ya puede publicar. |
| 2 | Rechazo | Queda motivo visible para la entidad. |
| 3 | Dinero | Aunque se apruebe, no existe recaudo de dinero. Nivel 2 no lo habilita. |
| 4 | Visita | No es paso obligatorio; solo si el validador la marca como necesaria. |
| 5 | Complemento | El motivo queda visible; la entidad puede reenviar evidencias; el badge sigue `en_revision` (no hay sello N1/N2). |

### HU-09 Gestionar postulaciones y entregar

| Campo | Contenido |
|---|---|
| ID | HU-09 |
| Épica | E-03 |
| RF | RF-13, RF-14, RF-15 |
| Rol | Como entidad |
| Característica | quiero revisar postulaciones, preseleccionar y registrar la entrega |
| Razón | para liberar un cupo con trazabilidad |
| Prioridad | Must |

| # | Escenario | Criterio |
|---|---|---|
| 1 | Tablero | Veo puntaje y respuestas por animal. |
| 2 | Preselección | Al preseleccionar, el animal pasa a `reservado`, sale del catálogo y no admite nuevas postulaciones. |
| 3 | Caída | Si se cae la preselección, esa postulación queda `rechazada` y el animal vuelve a `publicado`. |
| 4 | Entrega | Solo desde `reservado`: al marcar entregada, el animal pasa a `adoptado` y suma un cupo liberado. |
| 5 | Extra | Puedo pedir evidencia del hogar; se exige si hay necesidad especial. |
| 6 | Seguimiento | Queda estado de seguimiento a 15 días en el tablero (no hay correos automáticos). |

### HU-11 Cubrir un ítem

| Campo | Contenido |
|---|---|
| ID | HU-11 |
| Épica | E-04 |
| RF | RF-17, RF-18, RF-20 |
| Rol | Como donante y como entidad |
| Característica | quiero reservar un ítem y que el refugio confirme que llegó |
| Razón | para que la donación sea trazable |
| Prioridad | Must |

| # | Escenario | Criterio |
|---|---|---|
| 1 | Reserva | El ítem pasa a `reservado` y el donante deja contacto. |
| 2 | Confirmación | Con evidencia, pasa a `cubierto` y sale en bitácora pública sin datos personales del donante. |
| 3 | Caducidad | A los 7 días sin confirmación vuelve a `pendiente` (**Should**, RF-19). No bloquea el DoD Must de reservar y confirmar. |

La historia es **Must** en reservar y confirmar (RF-17, RF-18, RF-20). La caducidad automática es Should.
