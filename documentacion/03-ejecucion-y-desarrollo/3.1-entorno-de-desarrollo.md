## 3. Primer arranque

```bash
# 1. Base de datos
# En Fedora, `podman compose` suele fallar si no está el plugin.
# Si el contenedor ya existe (nombre refugios-pg):
podman start refugios-pg
# Primera vez, o si no existe el contenedor:
podman run -d --name refugios-pg \
  -e POSTGRES_USER=refugios \
  -e POSTGRES_PASSWORD=refugios_dev \
  -e POSTGRES_DB=refugios \
  -p 5433:5432 \
  -v refugios_pg:/var/lib/postgresql/data \
  postgres:16-alpine
# Si tienes el plugin: podman compose -f compose.yml up -d
# o: docker compose -f compose.yml up -d

# 2. API
cd api
cp .env.example .env
npx prisma migrate dev
npx prisma db seed
npm run start:dev

# 3. Cliente (otra terminal)
cd web
npm install
npm run dev
```

Abro [http://localhost:5173](http://localhost:5173). El cliente reenvía `/api` a `http://localhost:3000`.

Semilla: 19 localidades urbanas de Bogotá; un validador de piloto `validador@local.test` / `CambiaEsto123`; y **tres cuentas de ejemplo** (no son personas ni refugios reales) para demostrar cada rol:

| Rol | Correo | Contraseña | Qué deja listo |
|---|---|---|---|
| Entidad Nivel 1 | `entidad.ejemplo@local.test` | `EjemploLocal123` | Sello, dos animales en catálogo (Luna, Mote), un cupo ya liberado (Nube), un ítem pendiente y uno cubierto en bitácora |
| Adoptante | `adoptante.ejemplo@local.test` | `EjemploLocal123` | Las 5 preguntas ya respondidas y una postulación enviada a Luna |
| Donante | `donante.ejemplo@local.test` | `EjemploLocal123` | Puede reservar el ítem pendiente del hogar de ejemplo |

Nombres, historias e ítems llevan la marca **EJEMPLO**. Luna y Mote usan las fotos de `api/prisma/ejemplos/` (son ilustraciones de demostración, no animales reales). Si vuelvo a sembrar (`npx prisma db seed` en `api/`), se recrean esos datos y no se tocan cuentas que yo haya creado a mano con otro correo.

## 4. Variables de entorno

Están en `api/.env.example`. No copio `.env` al Git.

| Variable | Uso |
|---|---|
| `DATABASE_URL` | PostgreSQL |
| `JWT_SECRETO` | Firma de la cookie de sesión |
| `WEB_ORIGEN` | CORS si alguien llama a la API sin el proxy de Vite |
| `PUERTO` | API (3000) |
| `VALIDADOR_CLAVE_INICIAL` | Contraseña del usuario validador al hacer seed |

La sesión es una cookie `httpOnly` (`sid`). No hay pasarela ni claves de pago.

## 6. Incrementos demostrables

**Módulo 1 — HU-01 y HU-02.** Registro (adoptante, donante, entidad), consentimiento Ley 1581, localidad de Bogotá, sesión y cierre. El rol `validador` no se autoasigna. Una entidad recién creada **no puede publicar**.

**Módulo 2 — HU-03 y HU-04.** La entidad carga evidencias N1 (los tres documentos) o N2 (IDPYBA o COMVEZCOL). El validador (`validador@local.test` / `CambiaEsto123`) aprueba, rechaza con motivo o pide complemento. La visita es opcional. Aprobar pone el sello y `puedePublicar: true`. **No hay recaudo.** Las evidencias no son públicas: solo entidad dueña y validador.

**Módulo 3 — HU-05 y HU-06.** Entidad verificada publica animal (foto + historia ≥ 20, solo canino/felino). Catálogo público en `/` con filtros especie y localidad; **sin filtro por raza**. Perfil con historia primero y sello de la entidad. Visitante ve el catálogo; el adoptante con las 5 preguntas ve puntaje.

**Módulo 4 — HU-07 a HU-09.** Cinco preguntas de hogar. Puntaje 0–100 con frase explicable. Postulación (mayor de edad y vive en Bogotá). Entidad abre, preselecciona (`animal.estado = reservado`, sale del catálogo), cae o entrega. Entregar pone `adoptado` (métrica norte / cupo +1) y rechaza el resto de activas.

**Módulo 5 — HU-10 y HU-11.** Lista de deseos (alimento, medicina, aseo). El donante reserva un ítem y deja contacto privado. La entidad confirma con foto o check. La bitácora pública muestra ítem cubierto **sin datos del donante**. Reserva caduca a 7 días.

Cómo demostrar: abro [http://localhost:5173](http://localhost:5173) (catálogo). Entidad verificada → Publicar animal. Adoptante → 5 preguntas → postularse. Entidad → preseleccionar → marcar entrega. Donante → perfil de entidad → reservar ítem; entidad confirma.
