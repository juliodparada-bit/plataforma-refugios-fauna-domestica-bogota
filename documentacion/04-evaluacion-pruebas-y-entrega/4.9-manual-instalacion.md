**Qué es este documento, en una frase:** cómo dejar Mestizo **instalado** en un computador por primera vez (herramientas, clonar, dependencias, base de datos y `.env`).

El [4.4](4.4-despliegue.md) es el paso siguiente: encender el prototipo para la revisión. No los mezcles: instalar ≠ desplegar.

---

## 1. Qué vas a instalar

Mestizo vive en un repositorio Git con tres carpetas de código:

| Carpeta | Qué es |
|---|---|
| `api/` | El servidor (NestJS). Habla con PostgreSQL. |
| `web/` | La página que ves en el navegador (React + Vite). |
| `mobile/` | App Flutter de desarrollo. **Opcional.** No hace falta para la demo web. |

También hay `e2e/` (Playwright, un test de login fallido) y `documentacion/` (este expediente).

**Prisma**, en una frase: es la herramienta que crea las tablas en PostgreSQL a partir de `api/prisma/schema.prisma` (el “plano” de la base) y corre la semilla de cuentas de piloto.

## 2. Requisitos en el computador

| Herramienta | Para qué | Versión que usa el equipo |
|---|---|---|
| Git | Bajar el código | Cualquier 2.x |
| Node.js | Tests, y el camino de desarrollo con recarga | **22** (documentada). Brayan ha corrido tests con **Node 24** en Windows; no es un error. **No hace falta** para el arranque Compose de la revisión |
| npm | Instalar librerías si vas a editar código | 10 (viene con Node) |
| Docker **o** Podman + Compose | Levantar Postgres, API y web | Imagen `postgres:16-alpine` + `api/Dockerfile` + `web/Dockerfile` |
| Flutter + Android/iOS | Solo si vas a abrir `mobile/` | Flutter 3 / Dart 3 |

No hace falta Java, ni una cuenta en la nube, ni una tarjeta de crédito.

**Comprueba que existen:**

```bash
git --version
node --version
npm --version
docker --version
# o, si usas Podman:
podman --version
```

Si `node` no está: instálalo desde [https://nodejs.org](https://nodejs.org) (LTS 22) o, en Linux, con el gestor de tu distro. En Windows, el instalador oficial basta; Brayan ya trabaja con Node 24.

## 3. Clonar el repositorio

```bash
git clone https://github.com/juliodparada-bit/plataforma-refugios-fauna-domestica-bogota.git
cd plataforma-refugios-fauna-domestica-bogota
```

**Qué ver si salió bien:** existen las carpetas `api/`, `web/`, `mobile/`, `documentacion/` y el archivo `compose.yml`.

La rama demostrable del producto es `main`.

---

## 4. Copiar las variables de entorno

**Compose (revisión):** no copies `.env`. `compose.yml` inyecta `DATABASE_URL` hacia `postgres:5432` y el resto de claves con valores de ejemplo.

**Camino npm (desarrollo):** la API sí necesita `api/.env`. Ese archivo **no** va a Git. La plantilla sí:

```bash
cd api
cp .env.example .env
```

**Windows (PowerShell):**

```powershell
cd api
copy .env.example .env
```

**Qué hay dentro** (`api/.env.example`):

| Variable | Significado, en una frase |
|---|---|
| `DATABASE_URL` | Dónde está Postgres: usuario `refugios`, clave `refugios_dev`, puerto **5433**, base `refugios` |
| `JWT_SECRETO` | Palabra con la que se firman las sesiones. En local es de ejemplo; no la subas a Git |
| `WEB_ORIGEN` | Orígenes **extra** de CORS. Por defecto ya van `localhost` y `127.0.0.1` en 5173 y 4173 |
| `PUERTO` | Puerto de la API: **3000** |
| `VALIDADOR_CLAVE_INICIAL` | Contraseña del validador al sembrar (`CambiaEsto123`) |

**Qué ver si salió bien:** existe `api/.env` y tiene `5433` (no `5432`).

## 5. Instalar dependencias (npm)

Solo si vas a editar código o a correr tests. El arranque Compose de la revisión **no** usa estas carpetas: construye las imágenes.

Cada paquete tiene su propio `package.json`. Hay que instalar **dos veces** (API y web). No hay un `npm install` en la raíz.

```bash
cd api
npm install

cd ../web
npm install
```

**Qué ver si salió bien:** aparecen `api/node_modules/` y `web/node_modules/` y el comando termina sin `ERR!`.

Flutter (opcional):

```bash
cd mobile
flutter pub get
```

E2E del bootcamp (opcional; usa **pnpm**, no npm):

```bash
cd e2e
pnpm install
```

## 6. Crear la base y la semilla

**Revisión (recomendado).** Un comando construye API + web, aplica migraciones y siembra si la base está vacía:

```bash
./scripts/compose.sh up --build
```

Detalle y apagado: [4.4](4.4-despliegue.md).

**Solo Postgres**, si vas a correr Nest y Vite en el PC:

```bash
./scripts/compose.sh up -d postgres
```

Si no hay plugin Compose:

```bash
podman run -d --name refugios-pg \
  -e POSTGRES_USER=refugios -e POSTGRES_PASSWORD=refugios_dev \
  -e POSTGRES_DB=refugios -p 5433:5432 \
  -v refugios_pg:/var/lib/postgresql/data postgres:16-alpine
```

En el camino npm, tablas y datos de piloto:

```bash
cd api
npm run prisma:migrate
npm run prisma:seed
```

| Script | Qué hace |
|---|---|
| `prisma:migrate` | Aplica las migraciones de `api/prisma/migrations/` (crea/actualiza tablas) |
| `prisma:seed` | Crea Luna, Mote, Nube y las cuentas `@local.test`. No borra correos distintos |

**Qué ver si salió bien:** en Compose, `curl -s http://127.0.0.1:3000/localidades` devuelve JSON. En npm, `prisma:migrate` habla de migraciones aplicadas y `prisma:seed` termina sin error.

## 7. Scripts exactos de `package.json`

No hay que memorizarlos. Cópialos.

### `api/package.json`

| Script | Comando | Para qué |
|---|---|---|
| Instalar | `npm install` | Baja Nest, Prisma, Jest, etc. |
| Arrancar en desarrollo | `npm run start:dev` | Nest con recarga |
| Arrancar compilado | `npm run start:prod` | `node dist/src/main` (antes: `npm run build`) |
| Migrar | `npm run prisma:migrate` | Tablas |
| Semilla | `npm run prisma:seed` | Cuentas de piloto |
| Tests | `npm test` | Jest + cobertura (`--runInBand`) |
| Lint | `npm run lint` | ESLint **con** `--fix`. En T6 se midió **sin** `--fix` ([4.7](4.7-calidad-y-deuda.md)) |

### `web/package.json`

| Script | Comando | Para qué |
|---|---|---|
| Instalar | `npm install` | Baja React, Vite, Vitest |
| Desarrollo | `npm run dev` | Vite en **5173**, proxy a `127.0.0.1:3000` |
| Build | `npm run build` | Empaqueta para `preview` |
| Preview | `npm run preview` | Puerto **4173**, mismo proxy |
| Tests | `npm test` | Vitest + cobertura |

### `e2e/package.json`

| Script | Comando | Para qué |
|---|---|---|
| Tests | `pnpm test` | Playwright: login con clave mala |

### `mobile/`

| Comando | Para qué |
|---|---|
| `flutter pub get` | Dependencias Dart |
| `flutter run --dart-define=API_URL=…` | Corre la app contra la API |
| `flutter analyze` | Análisis estático |

## 8. Linux y Windows

Los comandos de `npm` y `git` son los mismos. Cambia el **cómo copias** y **cómo levantas Postgres**.

| Paso | Linux (Julio) | Windows (Brayan, Node 24) |
|---|---|---|
| Copiar entorno | `cp api/.env.example api/.env` | `copy api\.env.example api\.env` (PowerShell o `cmd`) |
| Postgres | Podman o Docker | Docker Desktop suele ser lo práctico |
| Abrir la web | [http://localhost:5173](http://localhost:5173) | Igual |
| Proxy | No lo toques: `127.0.0.1:3000` | Igual. No lo pongas en `localhost` |
| Cortafuegos | Si el celular no ve la API, abre el puerto **3000** | Windows Defender / firewall: regla de entrada TCP 3000 |

**No mezclar `localhost` y `127.0.0.1`.**

- El **navegador** puede usar `http://localhost:5173` o `http://127.0.0.1:5173`. Elige uno y quédate.
- El **proxy de Vite** (archivo, no lo edites para la demo) apunta a `http://127.0.0.1:3000`.
- `DATABASE_URL` usa `localhost:5433` en `.env.example`. Eso está bien: es el PC hablando con Docker, no el proxy de Vite.
- Flutter en teléfono **no** usa `localhost` (eso sería el propio teléfono). Usa la IP LAN del PC.

Node 24 en Windows: si `npm install` o `npm test` corren, sigue. No bajes a 22 “por si acaso” a menos que un error de motor lo pida.

## 9. Qué hacer si falla la instalación

### `npm install` se cae

- Sin red: reintenta. El sandbox del aula a veces corta el registro de npm.
- Permisos en Windows: cierra el antivirus un momento o corre la terminal “como administrador” solo si tu centro lo permite.
- Borra `node_modules` y `package-lock.json` **no**. El lock está versionado a propósito. Si está corrupto en tu copia local, `git checkout -- api/package-lock.json`.

### `prisma:migrate` no conecta

1. ¿El contenedor está arriba? `docker ps` / `podman ps` → `refugios-pg`.
2. ¿`.env` tiene puerto **5433**?
3. ¿Otro Postgres de la máquina está en 5433? `ss -tlnp | grep 5433` (Linux) o `netstat -ano | findstr 5433` (Windows).

### Puerto 5432 vs 5433

Si publicas `5432:5432` a mano, **rompe** el `.env.example`. Este proyecto usa **5433**. No “arregles” el compose para 5432.

### `EADDRINUSE` al instalar no aplica

Ese error sale al **arrancar**, no al instalar. Ve al [4.4 §6](4.4-despliegue.md).
