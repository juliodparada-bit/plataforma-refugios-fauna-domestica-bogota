## 2. Los tres servicios (y un opcional)

Mestizo no es un solo programa. Para la revisión hay que tener **tres** cosas encendidas al mismo tiempo. Flutter es opcional.

```
Navegador  →  http://localhost:5173
                  │
                  │  /api  (nginx en Compose, o proxy de Vite en desarrollo)
                  ▼
              API NestJS  (puerto 3000, escucha en 0.0.0.0)
                  │
                  ▼
         PostgreSQL 16  (contenedor refugios-pg, puerto 5433 en el PC)
```

| Servicio | Qué es, en una frase | Puerto en tu PC | Cómo se llama |
|---|---|---|---|
| 1. Base de datos | PostgreSQL guarda cuentas, animales, postulaciones | **5433** (no 5432) | Contenedor `refugios-pg` |
| 2. API | NestJS responde JSON (login, catálogo, postulaciones) | **3000** | Contenedor `refugios-api`, o `npm run start:dev` en `api/` |
| 3. Web | React pinta las pantallas | **5173** | Contenedor `refugios-web` (nginx), o `npm run dev` en `web/` |
| 4. Flutter (opcional) | Misma API en el celular; no abre un puerto propio | — | `flutter run` en `mobile/` |

**Por qué 5433 y no 5432.** El 5432 de la máquina ya estaba ocupado. `compose.yml` publica `5433:5432`: por fuera del contenedor usas **5433**; dentro de la red de Compose, Postgres sigue en 5432 y la API lo llama `postgres:5432`.

**Qué es `/api`.** El cliente web llama `http://localhost:5173/api/...`. En Compose, nginx quita el prefijo y reenvía a `http://api:3000/...`. En desarrollo con Vite, el proxy de `web/vite.config.ts` hace lo mismo hacia `http://127.0.0.1:3000`. No uses `localhost` en ese destino de Vite: en algunos equipos resuelve a IPv6 (`::1`) y la API no contesta.

**Qué es `0.0.0.0`.** La API no solo escucha en “este mismo PC”. Escucha en todas las interfaces de red. Por eso un celular en la misma Wi-Fi puede llamar a `http://192.168.x.x:3000`.

**Qué es JWT / cookie `sid`.** Al entrar, la API firma un token (JWT = un pase cifrado). En la **web** lo guarda en una cookie `httpOnly` llamada `sid` (el JavaScript del navegador no la lee). En **Flutter** el mismo token viaja en la cabecera `Authorization: Bearer …`. Si llegan las dos, gana la cookie (`api/src/auth/token.ts`).

## 3. Cómo ponerlo a correr (un comando)

Este es el camino de la revisión. Primera vez: [4.9](4.9-manual-instalacion.md) (Git + Podman o Docker). **No hace falta** `npm install` ni `api/.env` para esta vía.

Desde la raíz del repositorio:

```bash
./scripts/compose.sh up --build
```

Equivale a `podman compose up --build` o `docker compose up --build` (el script elige el que exista). Fedora sin plugin: `sudo dnf install podman-compose`, o el plugin Compose v2 en `~/.docker/cli-plugins/docker-compose`.

Qué hace, en orden:

1. Levanta PostgreSQL (`refugios-pg`).
2. Construye y arranca la API (`refugios-api`): aplica migraciones; si la base está vacía, corre la semilla.
3. Construye y arranca la web (`refugios-web`): nginx sirve `web/dist` y reenvía `/api` a la API.

**Qué ver si salió bien:**

```bash
curl -s http://127.0.0.1:3000/localidades | head
```

JSON con las 19 localidades urbanas de Bogotá. Luego abre [http://localhost:5173](http://localhost:5173).

La semilla **no** se vuelve a correr si ya hay localidades. Para forzarla otra vez (borra y recrea Luna, Mote y Nube):

```bash
./scripts/compose.sh exec api npm run prisma:seed
```

Para apagar los tres contenedores (el volumen `refugios_pg` **sigue** en el disco):

```bash
./scripts/compose.sh down
```

## 4. Alternativa: tres terminales (desarrollo diario)

Cuando cambias código y quieres recarga automática, Compose se queda corto: hay que reconstruir la imagen. En ese caso Postgres sigue en contenedor y API + web corren con npm.

Si ya usaste la sección 3, **apaga** los contenedores de API y web para no pelear por los puertos 3000 y 5173:

```bash
./scripts/compose.sh stop api web
```

Postgres puede seguir arriba (`refugios-pg`).

### 4.1 Terminal 1 — PostgreSQL

Si el contenedor ya existe:

```bash
podman start refugios-pg
# o: docker start refugios-pg
```

**Qué ver si salió bien:** `podman ps` (o `docker ps`) muestra `refugios-pg` y `0.0.0.0:5433->5432/tcp`.

### 4.2 Terminal 2 — API

```bash
cd api
cp .env.example .env   # solo si aún no existe
npm install            # solo la primera vez
npm run start:dev
```

**Qué es `start:dev`.** Arranca Nest y se queda “mirando” los archivos: si cambias código, reinicia solo. `DATABASE_URL` en `.env` usa **localhost:5433** (el PC habla con el puerto publicado). Compose, en cambio, usa el hostname `postgres` y el 5432 interno: no copies esa URL al `.env`.

**Qué ver si salió bien:** `Nest application successfully started`. `curl -s http://127.0.0.1:3000/localidades | head` devuelve JSON.

Si la base está vacía:

```bash
npm run prisma:migrate
npm run prisma:seed
```

### 4.3 Terminal 3 — Web

```bash
cd web
npm install            # solo la primera vez
npm run dev
```

**Qué ver si salió bien:** Vite imprime `Local: http://localhost:5173/`. Abre esa URL en el navegador.

## 6. Flutter en la misma revisión (companion)

No sustituye a la web. No se publica en tiendas. Habla **directo** con el puerto 3000 (Compose lo publica; no pasa por nginx ni por Vite).

```bash
cd mobile
flutter pub get
# Emulador Android (el PC se ve como 10.0.2.2):
flutter run --dart-define=API_URL=http://10.0.2.2:3000
# Simulador iOS:
flutter run --dart-define=API_URL=http://127.0.0.1:3000
# Teléfono físico, misma Wi-Fi. Cambia la IP por la de tu PC:
flutter run --dart-define=API_URL=http://192.168.1.20:3000
```

**Firewall.** Si el celular no conecta: permite el puerto 3000 en el cortafuegos del PC y usa la IP LAN, no `localhost`.

Guía larga: [mobile/README.md](../../mobile/README.md).

## 7. Qué hacer si falla

### El puerto 5173, 3000 o 5433 ya está ocupado

En Linux:

```bash
ss -tlnp | grep -E '5173|3000|5433'
```

Cierra el proceso viejo (otra terminal de Vite/Nest, u otro Compose) y vuelve a arrancar. No “cambies el puerto de la API a 3001” para la demo: el proxy apunta a **3000**.

Si mezclaste Compose con `npm run dev`/`start:dev`, apaga uno de los dos caminos:

```bash
./scripts/compose.sh stop api web
# o, en las terminales de npm: Ctrl+C
```

### La web abre pero el catálogo no carga / “La API no responde”

1. `curl http://127.0.0.1:3000/localidades` tiene que devolver JSON.
2. Abre la web como `http://localhost:5173` **o** `http://127.0.0.1:5173` y quédate en uno. Mezclarlos a veces trata la cookie `sid` como de otro origen.
3. En Compose, `./scripts/compose.sh logs api` y `./scripts/compose.sh logs web`.
4. En desarrollo con Vite, el proxy **siempre** va a `127.0.0.1:3000`. No lo cambies a `localhost`.

### Error de Prisma / “Can't reach database server”

1. `podman ps` (o `docker ps`): ¿está `refugios-pg`?
2. En el camino npm: abre `api/.env` y mira `DATABASE_URL`: el puerto debe ser **5433**.
3. En Compose: la API **no** lee `api/.env`. Usa `postgres:5432` por variable de `compose.yml`.

### Docker / Podman no arranca el contenedor

```bash
podman logs refugios-pg
# o: docker logs refugios-pg
```

Si el nombre `refugios-pg` ya existe pero está roto: no borres el volumen a ciegas (ahí está la base). Primero `start`. Si hay que recrear el piloto, usa la semilla o el [plan de respaldo 4.8](4.8-plan-de-respaldo.md).

### El nombre `refugios-pg` ya está en uso

El contenedor viejo (cuando Compose solo tenía Postgres) sigue con ese nombre. No borres el volumen a ciegas. Renómbralo y vuelve a levantar:

```bash
podman rename refugios-pg refugios-pg-prev
# o: docker rename refugios-pg refugios-pg-prev
./scripts/compose.sh up --build
```

### `./scripts/compose.sh` dice que no hay Compose / “Cannot connect to the Docker daemon”

- Fedora / RHEL: `sudo dnf install podman-compose`, o el plugin Compose v2 en `~/.docker/cli-plugins/docker-compose`.
- Socket de Podman (plugin v2): `systemctl --user start podman.socket`. El script lo intenta solo.
- Windows / macOS: Docker Desktop (trae `docker compose`).

### Entrar con la cuenta de piloto no funciona

La semilla no se corrió o la base está vacía:

```bash
./scripts/compose.sh exec api npm run prisma:seed
# camino npm:
cd api && npm run prisma:migrate && npm run prisma:seed
```

Luego vuelve a **Entrar**. Las cuentas no aparecen en la pantalla: cópialas de la tabla de la sección 5.

### Windows (Brayan, Node 24)

El camino Compose es el mismo (`docker compose up --build` desde la raíz). El camino npm son los mismos tres procesos. En PowerShell el `cd` funciona igual. Node 24 **sirve** para tests y `start:dev`; el número documentado del equipo es Node 22. Detalle: [4.9](4.9-manual-instalacion.md).

## 8. Cómo apagarlo

**Compose:**

```bash
./scripts/compose.sh down
```

**Tres terminales:** `Ctrl+C` en API y web; `podman stop refugios-pg` (o `docker stop refugios-pg`).

Los datos del volumen `refugios_pg` **siguen** en el disco. Las fotos subidas en Compose viven en el volumen `refugios_uploads`.
