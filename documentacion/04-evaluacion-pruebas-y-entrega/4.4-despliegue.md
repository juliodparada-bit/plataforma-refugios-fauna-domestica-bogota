## 2. Los tres procesos (y un opcional)

Mestizo no es un solo programa. Para la revisión hay que tener **tres** cosas encendidas al mismo tiempo. Flutter es opcional.

```
Navegador  →  http://localhost:5173  (cliente web Vite)
                  │
                  │  el proxy reescribe /api → http://127.0.0.1:3000
                  ▼
              API NestJS  (puerto 3000, escucha en 0.0.0.0)
                  │
                  ▼
         PostgreSQL 16  (contenedor refugios-pg, puerto 5433)
```

| Proceso | Qué es, en una frase | Puerto en tu PC | Cómo se llama |
|---|---|---|---|
| 1. Base de datos | PostgreSQL guarda cuentas, animales, postulaciones | **5433** (no 5432) | Contenedor `refugios-pg` |
| 2. API | NestJS responde JSON (login, catálogo, postulaciones) | **3000** | `npm run start:dev` en `api/` |
| 3. Web | React + Vite pinta las pantallas | **5173** | `npm run dev` en `web/` |
| 4. Flutter (opcional) | Misma API en el celular; no abre un puerto propio | — | `flutter run` en `mobile/` |

**Por qué 5433 y no 5432.** El 5432 de la máquina ya estaba ocupado. `compose.yml` publica `5433:5432`: por fuera de Docker usas **5433**; dentro del contenedor Postgres sigue en 5432.

**Qué es un proxy.** Vite (el servidor de la web) recibe `http://localhost:5173/api/...` y lo reenvía a `http://127.0.0.1:3000/...`. Está fijado en `web/vite.config.ts`. No uses `localhost` en ese destino: en algunos equipos `localhost` resuelve a IPv6 (`::1`) y la API no contesta.

**Qué es `0.0.0.0`.** La API no solo escucha en “este mismo PC”. Escucha en todas las interfaces de red. Por eso un celular en la misma Wi-Fi puede llamar a `http://192.168.x.x:3000`.

**Qué es JWT / cookie `sid`.** Al entrar, la API firma un token (JWT = un pase cifrado). En la **web** lo guarda en una cookie `httpOnly` llamada `sid` (el JavaScript del navegador no la lee). En **Flutter** el mismo token viaja en la cabecera `Authorization: Bearer …`. Si llegan las dos, gana la cookie (`api/src/auth/token.ts`).

## 3. Cómo ponerlo a correr (Linux o macOS)

Abre **tres terminales**. Si es la primera vez en esta máquina, termina primero el [4.9](4.9-manual-instalacion.md).

### 3.1 Terminal 1 — PostgreSQL

```bash
# Si el contenedor ya existe:
podman start refugios-pg
# o, si usas Docker:
docker start refugios-pg
```

**Qué ver si salió bien:** el comando imprime `refugios-pg` y no se queja. Comprueba:

```bash
podman ps
# o: docker ps
```

Debe aparecer `refugios-pg` y `0.0.0.0:5433->5432/tcp`.

**Si no existe el contenedor** (primera vez):

```bash
podman compose -f compose.yml up -d
# o: docker compose -f compose.yml up -d
```

### 3.2 Terminal 2 — API

```bash
cd api
# Solo si aún no existe .env:
cp .env.example .env
npm run start:dev
```

**Qué es `start:dev`.** Arranca Nest y se queda “mirando” los archivos: si cambias código, reinicia solo.

**Qué ver si salió bien:** en la terminal aparece algo como `Nest application successfully started` y no hay error de Prisma ni de puerto. En otra pestaña:

```bash
curl -s http://127.0.0.1:3000/localidades | head
```

Debe devolver un JSON con las 19 localidades urbanas de Bogotá.

### 3.3 Terminal 3 — Web

```bash
cd web
npm run dev
```

**Qué ver si salió bien:** Vite imprime `Local: http://localhost:5173/`. Abre esa URL en el navegador.

## 5. Flutter en la misma revisión (companion)

No sustituye a la web. No se publica en tiendas.

```bash
cd mobile
flutter pub get
# Emulador Android (el PC se ve como 10.0.2.2):
flutter run --dart-define=API_URL=http://10.0.2.2:3000
# Simulador iOS:
flutter run --dart-define=API_URL=http://127.0.0.1:3000
# Teléfono físico, misma Wi-Fi. Cambia la IP por la de tu PC:
flutter run --dart-define=API_URL=http://192.168.1.20:3000
```

**Firewall.** En el teléfono la app habla **directo** con el puerto 3000 (no pasa por Vite). Si el celular no conecta: permite el puerto 3000 en el cortafuegos del PC y usa la IP LAN, no `localhost`.

Guía larga: [mobile/README.md](../../mobile/README.md).

## 6. Qué hacer si falla

### El puerto 5173, 3000 o 5433 ya está ocupado

En Linux:

```bash
ss -tlnp | grep -E '5173|3000|5433'
```

Cierra el proceso viejo (otra terminal de Vite/Nest, o un Postgres anterior) y vuelve a arrancar. No “cambies el puerto de la API a 3001” para la demo: el proxy de Vite apunta a **3000**.

### La web abre pero el catálogo no carga / “La API no responde”

1. Mira la terminal 2: Nest tiene que estar corriendo.
2. Confirma `curl http://127.0.0.1:3000/localidades`.
3. Abre la web como `http://localhost:5173` **o** `http://127.0.0.1:5173` y quédate en uno. Mezclarlos a veces trata la cookie `sid` como de otro origen.
4. El proxy **siempre** va a `127.0.0.1:3000`. No lo cambies a `localhost`.

### Error de Prisma / “Can't reach database server”

1. `podman ps` (o `docker ps`): ¿está `refugios-pg`?
2. Abre `api/.env` y mira `DATABASE_URL`: el puerto debe ser **5433**.
3. Si no hay `.env`: `cp api/.env.example api/.env` (Linux) o el equivalente del [4.9](4.9-manual-instalacion.md).

### Docker / Podman no arranca el contenedor

```bash
podman logs refugios-pg
# o: docker logs refugios-pg
```

Si el nombre `refugios-pg` ya existe pero está roto: no borres el volumen a ciegas (ahí está la base). Primero `start`. Si hay que recrear el piloto, usa la semilla (`npm run prisma:seed`) o el [plan de respaldo 4.8](4.8-plan-de-respaldo.md).

### Entrar con la cuenta de piloto no funciona

La semilla no se corrió o la base está vacía:

```bash
cd api
npm run prisma:migrate
npm run prisma:seed
```

Luego vuelve a **Entrar**.

### Windows (Brayan, Node 24)

Los mismos tres procesos. En PowerShell el `cd` funciona igual. Si `podman` no existe, usa Docker Desktop (`docker start refugios-pg`). Node 24 **sirve** para esta revisión; el número documentado del equipo es Node 22. Detalle: [4.9](4.9-manual-instalacion.md).

## 7. Cómo apagarlo

No es obligatorio apagar Postgres entre sesiones. Para soltar CPU:

1. En las terminales de API y web: `Ctrl+C`.
2. Base: `podman stop refugios-pg` (o `docker stop refugios-pg`).

Los datos del volumen `refugios_pg` **siguen** en el disco.
