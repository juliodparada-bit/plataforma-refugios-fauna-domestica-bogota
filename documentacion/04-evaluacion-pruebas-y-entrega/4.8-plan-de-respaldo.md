**Qué es este documento, en una frase:** cómo no perder el código ni los datos de piloto, y cómo volver a dejar Mestizo usable si se rompe el computador o la base.

No hay cron, no hay AWS Backup, no hay snapshot en la nube, no hay disco externo institucional. **No se inventa.** Lo que hay es GitHub (código) + un dump de Postgres (datos) + la semilla (recrear el piloto).

---

## 1. Qué se respalda y qué no

| Cosa | ¿Respaldada? | Dónde |
|---|---|---|
| Código fuente (`api/`, `web/`, `mobile/`, `e2e/`) | Sí | GitHub: [plataforma-refugios-fauna-domestica-bogota](https://github.com/juliodparada-bit/plataforma-refugios-fauna-domestica-bogota) |
| Expediente (`documentacion/`) | Sí | El mismo repositorio |
| Esquema de la base (tablas) | Sí | `api/prisma/schema.prisma` + `api/prisma/migrations/` en Git |
| Datos de piloto (Luna, cuentas `@local.test`) | Recreable | `api/prisma/seed.ts` y fotos de ejemplo en `api/prisma/ejemplos/` |
| Datos que cargues a mano en local | Solo si haces un dump | Comando de la sección 3. **No hay tarea automática** |
| Fotos y evidencias subidas en local (`uploads/`) | **No** | La carpeta está en `.gitignore`. Si se borra el disco, se pierden |
| `api/.env` y `JWT_SECRETO` | **No** (a propósito) | Secretos no van a Git. Se reconstruyen copiando `.env.example` |
| Cuentas reales de un refugio | No aplica | El prototipo no tiene piloto en internet ni usuarios reales |

## 2. Copia del código (GitHub)

Cada `git push` deja el código en el remoto. Eso **es** la copia de seguridad del producto y del expediente.

```bash
git status
git push origin HEAD
```

**Qué ver si salió bien:** GitHub muestra el commit en la rama. La demostrable del producto es `main` (`ccac6b5` al 25 de noviembre de 2026).

Si el disco local muere:

```bash
git clone https://github.com/juliodparada-bit/plataforma-refugios-fauna-domestica-bogota.git
```

Luego el [4.9](4.9-manual-instalacion.md) (instalar) y el [4.4](4.4-despliegue.md) (arrancar).

No hay segundo remoto (GitLab, Drive, USB) documentado. Si el equipo quiere uno, es decisión posterior: hoy no existe.

## 3. Copia de la base (dump de Postgres)

PostgreSQL corre en el contenedor **`refugios-pg`**. `pg_dump` es el programa de Postgres que escribe un archivo SQL con las tablas y los datos.

**Hacer la copia** (el contenedor tiene que estar encendido):

```bash
# Docker
docker exec refugios-pg pg_dump -U refugios refugios > respaldo-refugios.sql

# Podman
podman exec refugios-pg pg_dump -U refugios refugios > respaldo-refugios.sql
```

**Qué ver si salió bien:** el archivo `respaldo-refugios.sql` pesa más que unos cuantos bytes y empieza con comentarios `--` de `pg_dump`. Guárdalo **fuera** del repo (no se versiona: puede traer datos de ejercicio).

**Qué no hace este dump:** no copia `uploads/` (fotos). Si necesitas las fotos, copia a mano la carpeta `api/uploads/` al mismo sitio donde guardas el `.sql`.

No hay script en `package.json` ni Action de GitHub que corra esto todas las noches.

## 4. Cómo restaurar

Hay dos caminos. Elige según lo que se perdió.

### 4.1 Se perdió el computador, pero el piloto de semilla basta

Es el caso de la sustentación T6. No hace falta el dump.

1. Clonar ([4.9](4.9-manual-instalacion.md)).
2. `cp api/.env.example api/.env` (vuelve el `JWT_SECRETO` de ejemplo).
3. Levantar `refugios-pg`.
4. `cd api && npm install && npm run prisma:migrate && npm run prisma:seed`.
5. Encender API y web ([4.4](4.4-despliegue.md)).

La semilla **recrea** Luna, Mote, Nube, el sello de Kennedy y las cuentas `@local.test`. Copia las fotos de ejemplo otra vez a `uploads/`.

### 4.2 Quieres los datos del dump (no solo la semilla)

1. Contenedor arriba, `.env` con `5433`.
2. Migraciones aplicadas (`npm run prisma:migrate`) **o** una base vacía con el mismo esquema.
3. Restaurar:

```bash
# Docker
cat respaldo-refugios.sql | docker exec -i refugios-pg psql -U refugios -d refugios

# Podman
cat respaldo-refugios.sql | podman exec -i refugios-pg psql -U refugios -d refugios
```

**Windows (PowerShell):** `Get-Content respaldo-refugios.sql | docker exec -i refugios-pg psql -U refugios -d refugios`

4. Si tenías fotos, vuelve a poner `api/uploads/`. Si no, las rutas en la base apuntarán a archivos que no existen: las fichas cargan sin foto o con error de imagen.

**Qué ver si salió bien:** entrar con `entidad.ejemplo@local.test` / `EjemploLocal123` y ver el catálogo.

### 4.3 Se perdió solo `uploads/`

Las filas de la base siguen. Las imágenes no. Opciones honestas:

- Volver a sembrar (`npm run prisma:seed`) para las fotos de Luna/Mote/Nube.
- Volver a subir las fotos desde la interfaz (cuenta / alta de animal / evidencias).

### 4.4 Se perdió `.env`

```bash
cp api/.env.example api/.env
```

Las sesiones viejas dejan de servir: el `JWT_SECRETO` de ejemplo es otro que el que tenías. Vuelve a **Entrar**. Eso es esperado.

## 5. Frecuencia recomendada (sin automatizar)

| Cuándo | Qué hacer |
|---|---|
| Cada cambio de código que importe | `git push` (ya es el hábito del [3.4](../03-ejecucion-y-desarrollo/3.4-git-flow.md)) |
| Antes de una demo o de borrar el contenedor | Un `pg_dump` a un USB o carpeta fuera del repo |
| Después de cargar datos que no quieras perder | Dump + copia de `uploads/` |
| Cada noche / cada hora | **No está configurado.** Si el instructor pregunta por cron: no hay |

---

## 6. Lo que este plan no cubre

- Recuperar un `JWT_SECRETO` olvidado (se regenera; la gente vuelve a entrar).
- Fotos que solo existían en el disco local.
- Alta disponibilidad ni réplica de Postgres.
- Copias cifradas en S3, Glacier, Time Machine institucional.
- El piloto en internet: **no existe**, así que no hay nada “en producción” que respaldar.

Si T7 abre un piloto HTTPS, este archivo se reescribe con el medio real (disco del hosting, dump programado, secreto distinto). Hasta entonces, GitHub + dump + semilla es el plan.
